# Петрострой · Контент-Завод

Telegram-бот, который превращает голосовые сообщения, фото и текстовые идеи
в готовые посты для соцсетей строительной компании «Петрострой».

Бот **никогда не публикует сам** — только генерирует черновики. Публикация в VK
на текущем этапе ручная (копипаст из бота).

## Возможности

- **Голос + фото** — голосовое → расшифровка (Whisper) → правка строительных терминов
  по глоссарию → извлечение фактов → генерация поста → прикрепление фото
- **Своя идея** — текст → извлечение фактов → генерация версий для VK / Telegram / Shorts
- **Фото + текст** — 1–10 фото (+ подпись) → Claude-vision описывает стройку → генерация поста
- **Рубрика вручную** — выбрать одну из 9 рубрик и задать тему
- **Контент-план на неделю** — статический шаблон (`/план`)
- **Контент-план на месяц** — генерация ~16 тем по рубрикам с заменой отдельных пунктов,
  затем написание поста по любому пункту плана (`/месяц`)
- **Review-кнопки** у каждого черновика — опубликовать (одобрить), переписать,
  сменить рубрику, выбрать фото, удалить
- **Статистика** постов (`/стат`) и **расходы на ИИ** за 30 дней (`/расходы`, только owner)
- **Rate-limit** — 5 сообщений в минуту на пользователя (настраивается)
- **Учёт стоимости** — каждый вызов ИИ пишется в таблицу `generation_log`
  (операция, модель, токены, стоимость в ₽, задержка)

## Как работает генерация

| Этап | Модель | Где в коде |
|------|--------|------------|
| Расшифровка голоса | `whisper-1` (OpenAI) | `services/transcription.py` |
| Правка терминов по глоссарию | `claude-sonnet-4-6` | `services/correction.py` |
| Извлечение фактов + выбор рубрики | `claude-sonnet-4-6` | `services/extraction.py` |
| Генерация постов VK/TG/Shorts | `claude-sonnet-4-6` | `services/generation.py` |
| Факт-чек (убирает непроверяемые цифры) | `claude-sonnet-4-6` | `services/generation.py` |
| Описание фото со стройки | `claude-sonnet-4-6` (vision) | `handlers/photo_post.py` |
| Контент-план на месяц | `claude-haiku-4-5-20251001` | `services/month_plan.py` |

Оркестрация этапов — в `services/pipeline.py`. Если рубрика определена
с уверенностью `< 0.6` — бот предлагает выбрать её вручную, по умолчанию `expertise`.

## Роли

Указываются в `.env` (`INITIAL_USERS`). Меню подстраивается под роль.

| Роль | Доступ |
|------|--------|
| `marketer` | Все режимы и команды |
| `foreman` (прораб) | Только «Голос + фото» — остальные режимы отвечают отказом |
| `owner` | Всё, что у `marketer`, плюс `/расходы`; при `REQUIRE_OWNER_APPROVAL=true` — согласование постов маркетологов |

## Главное меню (inline-кнопки)

Появляется по `/старт`. Набор кнопок зависит от роли.

| Кнопка | callback | Роли, которым доступно |
|--------|----------|-----------------------|
| 💡 Своя идея | `mode:idea` | marketer, owner |
| 📋 Из тренда (скоро) | `mode:trend_soon` | marketer, owner — заглушка (Фаза 3) |
| 🎤 Голос + фото | `mode:voice` | все роли |
| 🖼 Фото + текст | `mode:photo_post` | кнопка видна всем, но прорабу режим недоступен |
| 📊 Статистика | `cmd:stat` | marketer, owner |
| 📅 План | `cmd:plan` | marketer, owner |
| 🗓 Контент-план на месяц | `cmd:month_plan` | marketer, owner |
| 💰 Расходы | `cmd:expenses` | только owner |

## Команды бота (текстовые)

| Команда | Описание |
|---------|----------|
| `/старт` | Главное меню |
| `/идея [текст]` | Создать пост из идеи (без текста — бот попросит его следующим сообщением) |
| `/рубрика` | Выбрать рубрику и сгенерировать пост по теме |
| `/план` | Контент-план на неделю (статический шаблон) |
| `/месяц` | Сгенерировать контент-план на месяц |
| `/стат` | Статистика постов |
| `/расходы` | Затраты на ИИ за 30 дней (только owner) |
| `/готово` | Завершить добавление фото к посту |

Отдельной команды для голоса нет — просто отправьте боту голосовое сообщение,
оно обрабатывается в любом состоянии.

## Рубрики

9 рубрик хранятся в БД (таблица `rubrics`, заполняется при старте из `db/seed.py`),
у каждой — свой промт генерации и лимиты по числу знаков:

🎬 Видео-клип · 📐 Планировка · 😱 Страшилка · 🏠 Дом сдан · 🔧 Экспертиза ·
⚔️ Баттл · 💡 Лайфхак · 👷 Команда · 🏆 Статус

Также при старте заполняется таблица `trends` (9 бенчмарков конкурентов) — задел под Фазу 3.

## Быстрый старт

```bash
cd petrostroy-content-factory
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполните TELEGRAM_TOKEN, OPENAI_API_KEY, ANTHROPIC_API_KEY, INITIAL_USERS
python -m bot.main
```

Бот работает через long-polling. БД (SQLite) и все таблицы создаются автоматически
при первом запуске, туда же засеиваются рубрики, тренды и пользователи из `.env`.

Требуется Python 3.11+ (используется синтаксис `str | None`).

## Переменные окружения

| Переменная | Обяз. | По умолчанию | Назначение |
|------------|:----:|--------------|------------|
| `TELEGRAM_TOKEN` | да | — | Токен бота от @BotFather |
| `OPENAI_API_KEY` | да | — | Для Whisper (расшифровка голоса) |
| `ANTHROPIC_API_KEY` | да | — | Для Claude (правка, факты, генерация, vision) |
| `DATABASE_URL` | нет | `sqlite+aiosqlite:///./data/content_factory.db` | Строка подключения SQLAlchemy async |
| `REQUIRE_OWNER_APPROVAL` | нет | `false` | `true` — посты маркетолога уходят на согласование owner |
| `RATE_LIMIT_PER_MINUTE` | нет | `5` | Лимит сообщений в минуту на пользователя |
| `INITIAL_USERS` | нет | пусто | Начальные пользователи, см. ниже |
| `VK_COMMUNITY_TOKEN` | нет | пусто | Фаза 2 (VK API) |
| `VK_GROUP_ID` | нет | пусто | Фаза 2 (VK API) |

Ставки для расчёта стоимости ИИ заданы в коде (`bot/config.py`), не через `.env`:
Whisper — 10 ₽/мин, Claude — 300 ₽ / 1 500 ₽ за 1M входных / выходных токенов.

## Настройка пользователей

Формат `INITIAL_USERS` — записи `telegram_id:role:Имя` через запятую:

```
INITIAL_USERS=123456789:marketer:Дмитрий,987654321:foreman:Бригадир,111222333:owner:Владелец
```

Записи с уже существующим `telegram_id` пропускаются. Пользователи без записи
(и неактивные) получают «⛔ нет доступа». Свой ID можно узнать у @userinfobot.

## Модель данных

SQLite, SQLAlchemy 2.x (async). Основные таблицы:

- `users` — telegram_id, роль, имя, активность
- `posts` — режим, рубрика, статус, исходник (транскрипт/идея), факты (JSON),
  тексты `content_vk` / `content_tg` / `content_shorts`, хештеги, поля согласования
- `media` — фото поста (telegram_file_id, порядок, выбрано ли для публикации)
- `rubrics` — 9 рубрик с промтами и лимитами знаков
- `trends` — бенчмарки конкурентов (задел под Фазу 3)
- `metrics` — лайки/комменты/репосты/просмотры/ER по платформам (Фаза 2)
- `generation_log` — каждый вызов ИИ: операция, модель, токены, стоимость ₽, задержка

### Статусы поста

```
draft ──► pending_approval ──► approved
  └──────────────────────────► approved      (если REQUIRE_OWNER_APPROVAL=false)
draft ──► rejected                            (кнопка «Удалить»)
```

Бот доводит пост до `approved` и выдаёт текст для ручной вставки в VK.
Статус `published` и таблица `metrics` — под Фазу 2 (VK API).

## Фазы разработки

- **Фаза 1 (MVP)** — генерация + ручная публикация ← **текущая**
- **Фаза 2** — VK API, отложенный постинг, аналитика T+24 / T+48 (`scheduler/`)
- **Фаза 3** — тренд-библиотека в боте, ИИ-выбор фото, SEO-блог

## Что не входит в репозиторий

По `.gitignore` не коммитятся: `.env` (реальные токены), `data/` (БД с пользователями
и постами), `logs/`, `.venv/`, `__pycache__/`, `.DS_Store`. Весь исходный код —
в репозитории; для запуска нужен только свой `.env` (шаблон — `.env.example`).
